# 회고와 측정

> 작업 체계가 실제로 도움이 되는지 숫자로 봅니다. 작업마다의 값은 `docs/board.md`의 "운영 기록" 표에 적고, 여기에는 몇 사이클마다 모아 본 결과와 마찰을 적습니다.

## 측정 항목
| 항목 | 재는 법 | 언제 적나 | 살펴볼 신호 |
|---|---|---|---|
| 작업별 시작–머지 시간 | `/assign` 시각부터 `/merge` 시각까지 | `/merge` | 같은 크기 작업인데 점점 길어짐 |
| 승인 대기 시간 | 사용자 승인을 요청한 뒤 답을 받기까지 걸린 시간의 합 | `/merge` | 걸린 시간의 절반 이상이 대기 |
| 검증 차수 | 1차 / 2차 / 사용자에게 올림 | `/verify` | 2차가 잦음 (완료 기준이나 체크리스트가 약함) |
| 확정 지적 / 오탐 | 확정된 높음 지적 수 / `finding-verifier`가 반박한 수 | `/verify` | 오탐이 확정보다 많음 (기준이 모호함) |
| 세션별 토큰 | 각 세션의 사용량 (Orchestrator / Builder A / Builder B / Checker) | `/merge` | 한 세션만 크게 늘어남 (`/handoff` → `/clear` 필요) |

## 마찰 기록
> 같은 마찰이 **두 번째** 생기면 그때 커맨드, 규칙, 훅, 서브에이전트를 추가합니다. 첫 번째는 여기에 적기만 합니다.
