# 용어 사전 (유비쿼터스 언어)

> **계약 파일입니다.** `contract/*` 브랜치에서만 고칩니다. 바꾸려면 `/contract-change`로 요청합니다.
> 코드, 주석, UI 문구는 이 표의 용어와 영문 표기를 그대로 씁니다. "쓰지 않는 말" 열의 단어는 쓰지 않습니다.
> **[가정]** 표시는 실제 데이터 없이 정한 값입니다. M7 실험과 운영 결과를 보고 다시 정합니다.
> 작성: T-D1 (2026-10-05) · 근거: `docs/design/event-storming.md`, `docs/decisions/0001-bounded-contexts.md`

## 1. 고객과 실험 (`experiment`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 방문자 | `Visitor` | 고객 웹에 들어온 사람 1명. 로그인 없이 익명 쿠키에 담은 `visitorId`로 구분한다 [가정]. 기기나 브라우저가 바뀌면 다른 방문자다 | 유저, 회원 |
| 실험 | `Experiment` | 랜딩 소구점을 비교하는 A/B 테스트 1개 | 테스트(실험의 뜻으로) |
| 변형 | `Variant` | 실험 안의 A안·B안. A는 "최대 지원금", B는 "위약금 보전" | 버전, 시안 |
| 배정 | `Assignment` | 방문자에게 변형 하나를 정해 주는 일. 한 방문자는 한 실험에서 항상 같은 변형을 받는다 (고정 배정) | 할당 |
| 집계 제외 | `ExcludedFromAnalysis` | 배정에 실패한 방문자 표시. A안을 보여 주지만 노출·계산·전환 집계에서 모두 뺀다 | — |
| 노출 | `Exposure` | 배정된 변형의 랜딩을 방문자가 본 일. 방문자·실험당 첫 1회만 센다 [가정] | 조회수, 페이지뷰 |
| 계산기 사용자 | `CalculatorUser` | 예상 지원금 결과를 한 번 이상 본 방문자 | — |
| 전환 | `Conversion` | 방문자가 접수를 새로 만든 일. 방문자·실험당 1회만 센다. 재접수 합침은 전환이 아니다 | 성공, 가입 |

## 2. 요금제와 지원금 기준 (`catalog`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 요금제 | `Plan` | 통신사·속도·TV 포함 여부 조합과 월 요금 | 상품 |
| 지원금 기준표 | `RewardRateTable` | 요금제별 기본 지원금과 위약금 보전 한도를 적은 표. 계산기, 요금제 비교, 지원금 산정이 모두 이 표를 쓴다 | 정책표, 단가표 |
| 기준표 버전 | `RateTableVersion` | 기준표의 한 판. 한 번 만든 버전은 고치지 않고, 바꿀 때는 새 버전을 만든다. "버전"은 이 뜻으로만 쓴다 | — |
| 기본 지원금 | `BaseReward` | 기준표에 요금제별로 정한 지원금 | 기본금 |
| 약정 | `Commitment` | 고객이 지금 쓰는 인터넷의 의무 사용 기간 | 계약(약정의 뜻으로) |
| 남은 약정 개월 | `remainingCommitmentMonths` | 약정이 끝날 때까지 남은 개월 수. 0~36개월만 받는다 [가정] | 잔여기간 |
| 위약금 | `EarlyTerminationFee` | 약정 중에 해지하면 고객이 내는 돈. 고객이 입력하고, 모르면 기준표의 평균 위약금을 쓴다 [가정] | 해지금 |
| 위약금 보전액 | `FeeCoverage` | 위약금 가운데 지원금으로 대신 채워 주는 금액. `min(위약금, 보전 한도)`. 약정이 없으면 0원 | 위약금 지원 |
| 보전 한도 | `FeeCoverageCap` | 위약금 보전액의 상한. 30만 원 [가정] | 상한액 |
| 예상 지원금 | `RewardEstimate` | 기본 지원금 + 위약금 보전액. 계산기와 요금제 비교에서 보여 주는 금액. 접수 전의 안내 금액이다 | 견적, 최대 지원금(금액의 뜻으로) |
| 지원금 계산 | `calculateReward` | 기준표 버전 하나와 요금제·약정·위약금으로 예상 지원금을 구하는 공식. 계산기와 지원금 산정이 같은 공식을 쓴다 | — |

## 3. 접수와 상담 (`application`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 접수 | `Application` | 고객이 남긴 상담 요청 1건 | 신청, 리드, 문의 |
| 접수번호 | `applicationNumber` | 상담원이 보는 접수 식별 번호 | 신청번호 |
| 계산 결과 스냅샷 | `EstimateSnapshot` | 접수할 때 함께 남기는 계산 입력과 결과: 요금제, 약정 여부, 남은 약정 개월, 위약금, 기준표 버전, 예상 지원금 | — |
| 재접수 | `Resubmission` | 같은 전화번호로 마지막 접수 시각부터 7일 안에 다시 접수한 일. 기존 접수가 `접수`·`상담중`이면 새 접수를 만들지 않고 합친다 [가정] | 중복 신청 |
| 재접수 횟수 | `resubmissionCount` | 한 접수에 합쳐진 재접수 수. 어드민에 "재접수 N회"로 보인다 | — |
| 접수 상태 | `ApplicationStatus` | `접수(Submitted)` → `상담중(InConsultation)` → `개통완료(Activated)` / `취소(Cancelled)`. 앞으로만 바뀐다 | 진행상태 |
| 상담 | `Consultation` | 상담원이 접수 1건을 맡아 처리하는 과정. v1에서는 접수 상태 `상담중`으로만 나타낸다 | 콜 |
| 상담원 | `Counselor` | 어드민에 로그인해 접수를 처리하는 사람 | 상담사, 매니저 |
| 개통 | `Activation` | 고객 회선을 실제로 쓸 수 있게 된 일. 상담원이 `개통완료`로 바꿔 기록한다 | 설치(개통의 뜻으로), 가입완료 |
| 취소 | `Cancellation` | 개통 전에 접수를 끝내는 일. `접수`·`상담중`에서만 할 수 있다 | 해지, 철회 |
| 설치 희망 지역 | `installationRegion` | 고객이 회선 설치를 바라는 지역. 접수할 때 입력한다. "설치"는 이 용어에서만 쓴다 | 주소 |
| 상담 희망 시간대 | `preferredContactTime` | `오전(Morning)` / `오후(Afternoon)` / `저녁(Evening)` 가운데 하나 [가정] | 콜 시간 |
| 개인정보 동의 | `PrivacyConsent` | 접수에 필요한 필수 동의. 동의하지 않으면 접수할 수 없다 | 약관동의 |
| 전화번호 가림 | `MaskedPhoneNumber` | 가운데 자리를 가린 전화번호. 어드민의 기본 표시 | — |
| 전화번호 열람 | `PhoneNumberReveal` | 상담원이 가리지 않은 전화번호를 본 일. 누가, 언제 봤는지 남긴다 | 조회 |

## 4. 지원금 (`reward`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 지원금 | `Reward` | 개통한 접수에 지급하는 현금. 개통한 뒤에만 산정한다 | 사은품, 캐시백, 혜택금 |
| 지원금 산정 | `RewardCalculation` | 개통 뒤, 접수 때 남긴 기준표 버전으로 지원금 금액을 다시 계산해 확정하는 일 | 지원금 확정 |
| 지원금 상태 | `RewardStatus` | `산정됨(Calculated)` → `지급완료(Paid)`. 또는 `산정 대상 아님(NotEligible)` | — |
| 산정 대상 아님 | `NotEligible` | 개통했지만 지원금을 만들지 않는 상태. 지원금 기준표에 없는 요금제로 개통한 경우와, 계산 결과 스냅샷 없이 접수한 경우 [가정]. 고객이 본 적 없는 금액은 만들지 않는다. 지급 처리를 할 수 없다 | 미지급 |
| 지급 | `Payout` | 산정된 지원금을 고객에게 준 것으로 기록하는 일. 실제 송금은 하지 않고 `지급완료` 상태만 남긴다 | 송금, 정산, 환급 |

## 5. 도메인 이벤트
이름은 과거형 영문으로 씁니다. 타입 정의는 T-D2에서 `src/modules/shared/events/`에 씁니다.

| 이벤트 | 뜻 | 발행 BC | 받는 BC |
|---|---|---|---|
| `ApplicationSubmitted` | 새 접수가 만들어졌다 | `application` | `experiment` (전환 기록) |
| `ApplicationMerged` | 재접수가 기존 접수에 합쳐졌다 | `application` | 없음 (전환으로 세지 않음) |
| `ConsultationStarted` | 접수가 `상담중`이 됐다 | `application` | 없음 |
| `LineActivated` | 접수가 `개통완료`가 됐다 | `application` | `reward` (지원금 산정) |
| `ApplicationCancelled` | 접수가 `취소`됐다 | `application` | 없음 |
| `RewardCalculated` | 지원금 금액이 산정됐다 | `reward` | 없음 |
| `RewardPaid` | 지원금이 지급완료로 기록됐다 | `reward` | 없음 |

`experiment` 안에서만 쓰는 기록(`VariantAssigned`, `ExposureLogged`, `RewardEstimated`, `ConversionLogged`)은 BC 밖으로 나가지 않으므로 계약 이벤트가 아닙니다.

## 6. 쓰지 않는 이름
| 이름 | 이유 |
|---|---|
| `RewardScheduled` | 지급 조건 단계가 없어 "예약"이 아니다. `RewardCalculated`를 쓴다 |
| `ConsultationCompleted` | 상담의 결과는 개통이나 취소다. 화면에도 대응하는 상태가 없다 |
