# 용어 사전 (유비쿼터스 언어)

> **계약 파일입니다.** `contract/*` 브랜치에서만 고칩니다. 바꾸려면 `/contract-change`로 요청합니다.
> 코드, 주석, UI 문구는 이 표의 용어와 영문 표기를 그대로 씁니다. "쓰지 않는 말" 열의 단어는 쓰지 않습니다.
> **[가정]** 표시는 실제 데이터 없이 정한 값입니다. M7 실험과 운영 결과를 보고 다시 정합니다.
> 작성: T-D1 (2026-10-05) · 근거: `docs/design/event-storming.md`, `docs/decisions/0001-bounded-contexts.md`

## 1. 고객과 실험 (`experiment`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 방문자 | `Visitor` | 고객 웹에 들어온 사람 1명. 로그인 없이 익명 쿠키에 담은 `visitorId`로 구분한다 [가정]. 기기나 브라우저가 바뀌면 다른 방문자다 | 유저, 회원 |
| 실험 | `Experiment` | 랜딩 소구점을 A안·B안으로 나눠 비교하는 일 1개 | 테스트(실험의 뜻으로) |
| 변형 | `Variant` | 실험 안의 A안·B안. A는 "최대 지원금", B는 "위약금 보전" | 버전(변형의 뜻으로), 시안 |
| 배정 | `Assignment` | 방문자에게 변형을 정해 주는 일. 방문자가 처음 들어온 고객 화면에서 한 번만 결정하고, `experiment`가 `visitorId`별 배정 레코드(`A` / `B` / `제외`)로 남긴다 [가정]. 처음 화면이 랜딩이면 `A` 또는 `B`로 고정하고(실패하면 `제외`), 랜딩이 아니면(02·03·04) 영구히 `제외`다. 한 번 정한 값은 바뀌지 않는다 | 할당 |
| 집계 제외 | `ExcludedFromAnalysis` | 방문자 단위의 영구 `제외` 표시. 배정에 실패한 방문자와, 처음 들어온 화면이 랜딩이 아닌 방문자가 해당한다 (실험 대상은 랜딩 소구점이라 의도한 것). 나중에 랜딩에 와도 배정을 받지 않고 A안을 본다 [가정]. 이 방문자의 노출·계산·전환도 기록하되 `제외` 표시를 달고, 지표 1·2의 분모와 분자에 넣지 않는다 | — |
| 노출 | `Exposure` | 랜딩이 방문자에게 보인 일 (배정 변형 또는 `제외`). 방문자·실험당 첫 1회만 센다 [가정] | 조회수, 페이지뷰 |
| 계산기 사용자 | `CalculatorUser` | 03 지원금 계산기에서 계산을 실행해 `RewardEstimated`가 기록된 방문자. 02 요금제 비교의 카드 금액을 본 것은 넣지 않는다 | — |
| 전환 | `Conversion` | 방문자가 접수를 새로 만든 일. `experiment`가 `ApplicationSubmitted`를 받아 기록하고, 화면이 직접 기록하지 않는다. 판정 기준은 접수에 기록된 배정 변형 하나다. `visitorId`·실험당 1회만 센다. 재접수 합침은 전환이 아니다. 같은 사람이 다른 기기에서 새 접수를 만들면 두 번 셀 수 있다 (알려진 한계) [가정] | 성공(전환의 뜻으로), 가입(전환의 뜻으로) |

## 2. 요금제와 지원금 기준 (`catalog`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 요금제 | `Plan` | 통신사·속도·TV 포함 여부 조합과 월 요금 | 상품 |
| 지원금 기준표 | `RewardRateTable` | 요금제별 기본 지원금, 그리고 버전마다 하나씩인 평균 위약금과 보전 한도를 담은 표. 계산기, 요금제 비교, 지원금 산정이 모두 이 표를 쓴다 | 정책표, 단가표 |
| 기준표 버전 | `RateTableVersion` | 기준표의 한 판. 한 번 만든 버전은 고치지 않고, 바꿀 때는 새 버전을 만든다. "버전"은 이 뜻으로만 쓴다 | — |
| 기본 지원금 | `BaseReward` | 기준표에 요금제별로 정한 지원금 | 기본금 |
| 약정 | `Commitment` | 고객이 지금 쓰는 인터넷의 의무 사용 기간 | 계약(약정의 뜻으로) |
| 계산 입력 | `EstimateInput` | 지원금 계산에 넣는 값 4개 [가정]: 요금제(필수), 약정 남음 여부(필수, 예/아니요), 남은 약정 개월(약정 남음이 "예"일 때만 필수), 위약금(선택, 비우면 "모름"). 약정 남음이 "아니요"면 함께 들어온 남은 약정 개월과 위약금은 거절하지 않고 무시하며, 보전액 0원으로 계산한다 [가정]. 입력 4개 가운데 하나라도 채워졌는데 필수 조건을 다 채우지 못하면(위약금만 있는 경우 포함) "일부만 있음"이라 계산과 접수를 모두 거절한다. 존재하지 않는 요금제 ID도 거절한다. 전부 비었으면 계산 요청은 거절하고, 접수는 계산 없이 진행한다 | — |
| 남은 약정 개월 | `remainingCommitmentMonths` | 약정이 끝날 때까지 남은 개월 수. 약정 남음이 "예"일 때만 받는 필수 입력이다. 0~36 사이 정수 개월만 받는다 [가정]. 범위 밖이면 계산과 접수를 모두 거절한다 | 잔여기간 |
| 위약금 | `EarlyTerminationFee` | 약정 중에 해지하면 고객이 내는 돈. 선택 입력이고, 비우면 "모름"이라 평균 위약금을 쓴다. 0원 이상 1,000만 원 이하 정수 원만 받는다 [가정]. 범위 밖이면 계산과 접수를 모두 거절한다 | 해지금 |
| 평균 위약금 | `AverageEarlyTerminationFee` | 고객이 위약금을 모를 때 대신 쓰는 값. 기준표 버전에 속하고 버전마다 하나다 (요금제별 값이 아님) [가정] | — |
| 위약금 보전액 | `FeeCoverage` | 위약금 가운데 지원금으로 대신 채워 주는 금액. `min(위약금, 보전 한도)`. 약정이 없으면 0원 | 위약금 지원 |
| 보전 한도 | `FeeCoverageCap` | 위약금 보전액의 상한. 기준표 버전에 속하고 버전마다 하나다 (요금제별 값이 아님). 30만 원 [가정] | 상한액 |
| 예상 지원금 | `RewardEstimate` | 기본 지원금 + 위약금 보전액. 계산기와 요금제 비교에서 보여 주는 금액. 접수 전의 안내 금액이다. 02 요금제 비교의 카드 금액은 약정 없음(보전액 0원) 기준, 곧 기본 지원금이라서 계산기에서 약정 없음을 고르면 같은 숫자가 나온다 | 견적, 최대 지원금(금액의 뜻으로) |
| 지원금 계산 | `calculateReward` | 기준표 버전 하나와 요금제·약정·위약금으로 예상 지원금을 구하는 공식. 계산기와 지원금 산정이 같은 공식을 쓴다 | — |

## 3. 접수와 상담 (`application`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 접수 | `Application` | 고객이 남긴 상담 요청 1건. 이름, 전화번호, 개인정보 동의는 필수이고 설치 희망 지역과 상담 희망 시간대는 선택이다 [가정] | 신청, 리드, 문의 |
| 접수번호 | `applicationNumber` | 상담원이 보는 접수 식별 번호 | 신청번호 |
| 계산 결과 스냅샷 | `EstimateSnapshot` | 접수할 때 서버가 계산 입력으로 그 시점의 현재 기준표 버전 [가정]을 써서 다시 계산해 남기는 값. 필드: 계산 입력 4개(위약금은 "입력값" / "모름" / "해당 없음(약정 아니요)" 가운데 하나. 약정 아니요일 때 무시한 값은 남기지 않음), 적용 위약금(입력값이면 그 값, 모름이면 평균 위약금, 해당 없음이면 0원), 기준표 버전, 예상 지원금(기본 지원금, 위약금 보전액, 합계) [가정]. 클라이언트가 보낸 버전·금액은 쓰지 않는다. 요금제는 있지만 기준표 버전에 없는 요금제는 계산할 수 없으므로 스냅샷이 없다 | — |
| 방문자 ID (접수) | `visitorId` | 접수를 만든 방문자의 ID. 접수의 사실로 남긴다 | — |
| 배정 변형 (접수) | `assignedVariant` | 접수할 때 읽은 그 방문자의 배정 레코드 값. `A` / `B` / `제외(Excluded)`. 레코드가 없으면 `제외`다. v1의 실험은 하나뿐이라 접수는 변형 하나만 담는다 [가정] | — |
| 전화번호 | `PhoneNumber` | 숫자만 남겨 정규화한 뒤 저장하고 비교한다. 01로 시작하는 10~11자리만 받는다 [가정]. `010-1234-5678`과 `01012345678`은 같은 번호다 | — |
| 재접수 | `Resubmission` | 같은 전화번호로 마지막 접수 시각(합침 포함)부터 168시간(7일) 미만에 다시 접수한 일. 서버 시각(UTC)으로 비교한다. 기존 접수가 `접수`·`상담중`이면 새 접수를 만들지 않고 합친다. 합칠 때마다 168시간 창이 다시 시작된다 (의도). `상담중`이면 연락처성 정보만 바꾸고 계산 결과 스냅샷은 바꾸지 않는다 [가정] | 중복 신청 |
| 재접수 횟수 | `resubmissionCount` | 한 접수에 합쳐진 재접수 수. 어드민에 "재접수 N회"로 보인다 | — |
| 접수 상태 | `ApplicationStatus` | `접수(Submitted)` → `상담중(InConsultation)` → `개통완료(Activated)` / `취소(Cancelled)`. 앞으로만 바뀐다. 허용 전이는 `접수 → 상담중 → 개통완료`, `접수 → 취소`, `상담중 → 취소`뿐이다 [가정] | 진행상태 |
| 상담 | `Consultation` | 상담원이 접수 1건을 맡아 처리하는 과정. v1에서는 접수 상태 `상담중`으로만 나타낸다 | 콜 |
| 상담원 | `Counselor` | 어드민에 로그인해 접수를 처리하는 사람. 상담원 계정과 `counselorId`의 주인은 `shared`의 어드민 인증이고, 다른 BC는 `counselorId`만 기록한다 | 상담사, 매니저 |
| 개통 | `Activation` | 고객 회선을 실제로 쓸 수 있게 된 일. 상담원이 `개통완료`로 바꿔 기록한다 | 설치(개통의 뜻으로), 가입완료 |
| 취소 | `Cancellation` | 개통 전에 접수를 끝내는 일. `접수`·`상담중`에서만 할 수 있다 [가정] | 해지(취소의 뜻으로), 철회 |
| 설치 희망 지역 | `installationRegion` | 고객이 회선 설치를 바라는 지역. 접수할 때 입력하는 선택 항목이다 [가정]. "설치"는 회선을 설치하는 방문 작업의 뜻으로 쓰고, 개통의 뜻으로는 쓰지 않는다 | 주소(지역의 뜻으로) |
| 상담 희망 시간대 | `preferredContactTime` | `오전(Morning)` / `오후(Afternoon)` / `저녁(Evening)` 가운데 하나. 선택 항목이다 [가정] | 콜 시간 |
| 개인정보 동의 | `PrivacyConsent` | 접수에 필요한 필수 동의. 동의하지 않으면 접수할 수 없다. 동의한 사실과 시각을 접수에 남기고, 재접수를 합칠 때 갱신한다. 보관 기간과 파기는 v1 범위 밖이고, 실서비스에서는 필요하다 | 약관동의 |
| 전화번호 가림 | `MaskedPhoneNumber` | 가운데 자리를 가린 전화번호. 어드민 목록·상세 응답에는 가린 번호만 담는다. 검색은 뒷자리 4자리로만 한다 [가정] | — |
| 전화번호 열람 | `PhoneNumberReveal` | 상담원이 가리지 않은 전화번호를 본 일. 원래 번호는 열람 명령으로만 주고, 누가, 언제 봤는지 남긴다 | 조회(열람의 뜻으로) |

## 4. 지원금 (`reward`)
| 용어 | 영문 표기 | 정의 | 쓰지 않는 말 |
|---|---|---|---|
| 지원금 | `Reward` | 개통한 접수에 지급하는 현금. 개통한 뒤에만 산정한다 | 사은품, 캐시백, 혜택금 |
| 지원금 산정 | `RewardCalculation` | 개통 뒤, 접수 때 남긴 계산 결과 스냅샷의 입력과 기준표 버전으로 지원금 금액을 다시 계산해 정하는 일. 개통 요금제는 스냅샷의 요금제와 같다 (개통 때 요금제 변경은 v1 범위 밖) | 지원금 확정 |
| 지원금 상태 | `RewardStatus` | `산정됨(Calculated)` → `지급완료(Paid)`. 또는 `산정 대상 아님(NotEligible)` | — |
| 산정 대상 아님 | `NotEligible` | 개통했지만 지원금을 만들지 않는 상태. 접수에 계산 결과 스냅샷이 없으면(계산 없이 접수, 기준표에 없는 요금제) 이 상태가 된다 [가정]. 판단 근거는 접수 때 정해진다. 고객이 본 적 없는 금액은 만들지 않는다. 지급 처리를 할 수 없다 | 미지급 |
| 지급 | `Payout` | 산정된 지원금을 고객에게 준 것으로 기록하는 일. 실제 송금은 하지 않고 `지급완료` 상태만 남긴다 | 송금(지급의 뜻으로), 정산, 환급 |

## 5. 도메인 이벤트
이름은 과거형 영문으로 씁니다. 타입 정의는 T-D2에서 `src/modules/shared/events/`에 씁니다.
이벤트 payload에는 ID와 그 시점의 사실만 담고, 전화번호·이름 같은 개인정보는 넣지 않습니다.

| 이벤트 | 뜻 | 발행 BC | 받는 BC |
|---|---|---|---|
| `ApplicationSubmitted` | 새 접수가 만들어졌다 | `application` | `experiment` (전환 기록) |
| `ApplicationMerged` | 재접수가 기존 접수에 합쳐졌다 | `application` | 없음 (전환으로 세지 않음) |
| `ConsultationStarted` | 접수가 `상담중`이 됐다 | `application` | 없음 |
| `LineActivated` | 접수가 `개통완료`가 됐다 | `application` | `reward` (지원금 산정) |
| `ApplicationCancelled` | 접수가 `취소`됐다 | `application` | 없음 |
| `RewardCalculated` | 지원금 금액이 산정됐다 | `reward` | 없음 |
| `RewardPaid` | 지원금이 지급완료로 기록됐다 | `reward` | 없음 |

`experiment` 안에서만 쓰는 기록(`VariantAssigned`, `ExposureLogged`, `RewardEstimated`, `ConversionLogged`)은 BC 밖으로 나가지 않으므로 계약 이벤트가 아닙니다.
