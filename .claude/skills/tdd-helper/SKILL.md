# tdd-helper — 구현

## 0. 시작 조건
- `docs/checklists/<작업ID>.md`가 있어야 합니다. 없으면 구현하지 않고 `strategy-checklist`를 먼저 쓰라고 안내합니다.
- 현재 브랜치가 `main`이 아니어야 합니다. 구현은 worktree의 `feat/*` 브랜치에서 합니다.
- 체크리스트의 "수정 가능 경로" 밖은 고치지 않습니다.

## 1. 테스트 케이스마다 반복 (Red → Green → Refactor)
1. **Red:** 체크리스트의 테스트 케이스 하나를 테스트로 옮깁니다. 실행해서 **기대한 이유로** 실패하는지 확인합니다. 컴파일 에러나 import 실패는 기대한 실패가 아닙니다.
2. **Green:** 테스트를 통과하는 가장 단순한 코드를 씁니다.
3. **Refactor:** 테스트가 통과하는 상태를 유지하면서 이름과 구조를 정리합니다. 이름은 `docs/glossary.md`를 따릅니다.
4. 케이스 하나가 끝날 때마다 커밋합니다. 메시지 예: `test(application): 7일 안 중복 접수 병합`

## 2. 막혔을 때
- **계약이 부족함:** 계약 파일을 고치지 않습니다 (훅이 막습니다). 멈추고 `/contract-change`로 요청합니다.
- **체크리스트에 없는 결정이 필요함:** 추측하지 않습니다. 멈추고 Orchestrator에게 묻습니다.
- **같은 테스트를 3번 고쳐도 실패함:** 멈추고 원인을 정리해 보고합니다.

## 3. 마무리 검증
1. `npm run check`를 실행합니다 (타입 검사, 린트, 테스트, 아키텍처 검사).
2. 출력에서 **테스트 실행 건수와 통과 건수**를 직접 읽습니다. 0건이거나 건수가 안 보이면 캐시, 컴파일 실패, 필터 오타를 의심하고 다시 확인합니다.
3. `.skip`이나 `.only`가 남아 있지 않은지 확인합니다.

## 4. 리뷰 요청
`/review-request <작업ID>`로 리뷰를 요청합니다. 직접 머지하지 않습니다.
