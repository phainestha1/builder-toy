# 프론트엔드 (Next.js App Router)

- **화면의 기준:** `docs/screens.md`의 Figma 설계를 따릅니다. 설계와 다르게 만들어야 하면 이유를 리뷰 요청에 적습니다.
- **로직 호출:** 라우트와 컴포넌트는 BC의 `application` 유스케이스만 호출합니다. 금액 계산 같은 정책 로직을 컴포넌트에 두지 않습니다.
- **고객 화면 문구:** `docs/glossary.md`의 한국어 용어를 씁니다. 예를 들어 "신청"이나 "캐시백"이 아니라 "접수", "지원금"이라고 씁니다.
- **실험 이벤트:**
  - 고객 화면 라우트는 진입할 때 `experiment`의 배정 확인 유스케이스를 부르고, 랜딩은 노출 기록을 남깁니다.
  - 계산기(03)는 계산이 성공했을 때 `experiment`의 계산 기록 유스케이스를 부릅니다.
  - 전환은 화면이 기록하지 않습니다. `experiment`가 `ApplicationSubmitted` 이벤트를 받아 기록합니다.
  - 이벤트 이름과 속성은 계약에 정의된 것만 씁니다.
- **어드민:** `/admin` 아래 모든 경로는 로그인이 필요합니다. 서버에서 세션을 확인하고, 클라이언트 쪽 확인만으로 막지 않습니다.
- **개인정보:** 전화번호는 화면과 로그에서 가운데 자리를 가립니다 (`010-****-1234`).
