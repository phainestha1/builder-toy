# 테스트

테스트 도구는 프로젝트에 맞게 고릅니다. 검사 명령(`CHECK_CMD`, `.claude/project.conf`)이 테스트를 포함하고, 출력에 실행 건수와 통과 건수가 보이게 설정합니다.

- **TDD:** 실패하는 테스트를 먼저 쓰고, 실패하는 이유가 기대한 이유인지 확인한 뒤 구현합니다.
- **위치 (권장 기본 구조 기준):**
  - 도메인 테스트는 `src/modules/<구역>/domain/` 안
  - 유스케이스 테스트는 `src/modules/<구역>/application/` 안
  - E2E는 `e2e/`
- **정책 테스트:** `docs/prd.md`와 `docs/decisions/`의 정책·예외 케이스는 정책 하나당 테스트 하나 이상을 둡니다. 테스트 이름에 정책을 한국어로 적습니다.
  - 예: `"같은 요청을 7일 안에 다시 보내면 기존 요청에 합친다"`
- **경계값:** 날짜, 숫자 상한, 상태 전이처럼 경계가 있는 규칙은 경계 바로 안쪽과 바깥쪽을 둘 다 테스트합니다.
- **보고:** 결과는 항상 `테스트 실행 N / 통과 N`으로 보고합니다. 출력에서 실행 건수를 직접 읽습니다. 0건이거나 건수가 보이지 않으면 통과로 보고하지 않습니다.
- **하지 말 것:**
  - 건너뛰기·단독 실행 표시(예: `.skip`, `.only`, `@skip`)를 커밋하지 않습니다.
  - 테스트를 통과시키려고 기대값을 고치지 않습니다. 기대값이 틀렸다고 판단되면 이유를 보고합니다.
